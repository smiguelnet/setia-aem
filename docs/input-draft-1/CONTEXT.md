# AEM Website Development Guide - From Maven Archetype to Complete Website

# 1. Overview

This document describes the complete process to create an Adobe Experience Manager (AEM) website starting from the Maven Archetype project.

The guide includes:

* AEM architecture understanding
* Project structure
* Component strategy
* Authoring workflow
* Sling Models
* HTL
* Client Libraries
* Templates
* Website structure
* Synchronization between code and AEM Author

---

# 2. High-Level AEM Architecture

```text
Browser
  ↓
Dispatcher / CDN
  ↓
Publish Instance
  ↓
Sling Resource Resolver
  ↓
JCR Content
  ↓
HTL Component Rendering
```

Authoring flow:

```text
AEM Author UI
  ↓
JCR Repository
  ↓
Page/Component Content
```

---

# 3. Mental Model

```text
ui.apps
  = component definitions

core
  = Java models/services

ui.frontend
  = CSS/JS/assets

ui.content
  = initial site content, templates, policies

AEM Author
  = create and edit real pages
```

# 5. Responsibilities of Each Module

## 5.1 core

Contains backend Java logic.

Examples:

* Sling Models
* OSGi Services
* Servlets
* Schedulers
* Integrations

Example:

```java
@Model(adaptables = Resource.class)
public class HeroModel {

    @ValueMapValue
    private String title;

    public String getTitle() {
        return title;
    }
}
```

---

## 5.2 ui.apps

Contains reusable AEM component definitions.

Examples:

```text
HTL files
Dialogs
Component definitions
ClientLib definitions
Templates
```

Example:

```text
/apps/setia/components/hero
```

---

## 5.3 ui.frontend

Contains frontend source files.

Examples:

```text
SCSS
CSS
JavaScript
TypeScript
Images
Fonts
Icons
```

Compiled assets are copied into AEM clientlibs.

---

## 5.4 ui.content

Contains repository content exported to source control.

Examples:

```text
Initial pages
Editable templates
Policies
Site structure
Tags
Sample content
```

Usually represents:

```text

/conf
```

## 5.5 AEM Author

Used by:


# 6. Generate the AEM Project

Run:

```bash
mvn -B org.apache.maven.plugins:maven-archetype-plugin:3.3.1:generate \
  -DarchetypeGroupId=com.adobe.aem \
  -DarchetypeArtifactId=aem-project-archetype \
  -DarchetypeVersion=50 \
  -DappTitle="Setia" \
  -DappId="setia" \
  -DgroupId="br.com.setia" \
  -DaemVersion=cloud \
  -DfrontendModule=general \
  -DincludeExamples=n
```

---

# 7. Build and Install Locally

```bash
cd setia

mvn clean install -PautoInstallSinglePackage
```

Then open:

```text
http://localhost:4502
```

# 14. Use Sling Models When Logic Is Needed

Use Sling Models for:

```text
Formatting
Validation
API integrations
Fallback values
Lists
Business logic preparation
```

Example:

```java
@Model(adaptables = Resource.class)
public class HeroModel {

    @ValueMapValue
    private String title;

    @OSGiService
    private PromotionService promotionService;

    public String getTitle() {
        return title;
    }

    public String getPromotion() {
        return promotionService.getCurrentPromotion();
    }
}
```

---

# 15. HTL Rendering

# 20. Understanding JCR Content

Example:

```xml
<carousel
    sling:resourceType="setia/components/carousel"
    autoplay="false"
    delay="5000"/>
```

Meaning:

```text
A carousel component instance exists on the page.
```

The component implementation lives in:

```text
/apps/setia/components/carousel
```

The page content lives in:

```text
/content/setia/us/en/home
```

# 22. Typical Development Workflow

```text
1. Create reusable components in ui.apps
2. Create Sling Models in core
3. Create styles/scripts in ui.frontend
4. Deploy to AEM
5. Create templates in AEM Author
6. Create pages in AEM Author
7. Add components visually
8. Export important content/configuration into ui.content
9. Commit to Git
```
